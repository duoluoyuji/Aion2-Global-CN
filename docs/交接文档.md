## 0. 七条红线（违反任何一条都会让用户游戏起不来或汉化失效）

1. **只写 `Engine.locres`，绝对不要碰任何 `pak`。**
   本流程从开始到结束都不需要解包、解密、改 pak。改封在 pak 里的 `L10NString.dat` 会让整张表变问号（改 1 条和改 3 条一样）。已复现多次。
2. **两个入口必须物理互斥。**
   `en` / `en-US` 的 locres 存在时，会按 key 回退覆盖 `ja` / `ja-JP`。所以部署任一入口前，**先删掉另一入口的全部文件**，并在日志里逐条写明删了什么。
3. **不要改 `Engine.ini` 的 `Culture`。**
   工具只提示"入口要和游戏内语言一致"，绝不代改游戏设置。历史上的 `Ensure-JapaneseCulture` 已整段删除，别加回来。
4. **删文件即还原，不要做备份、不要恢复备份。**
   官方客户端不自带松散 locres，删掉四个文件立即回落官方原版。
5. **`.bat` 必须 GBK(936) + CRLF；`.ps1` 必须 UTF-8 with BOM。**
   LF 的 bat 会让 cmd 解析错乱（报 `'cal'` / `'-NoProfile'`，错误码 9009）；无 BOM 的 ps1 会让 PowerShell 5 按 ANSI 读中文，界面乱码且变量被吞。
6. **载荷哈希与诊断脚本里写死的基准必须同步。**
   `Aion2Diag.ps1` 顶部的 4 组尺寸 / SHA256 要随载荷一起变，否则诊断会把正常安装判成"未知汉化文件"。
   `build\build.ps1` 打包前已按实际载荷自动回写，不要再手工改这 4 组。
7. **`source_hash` 只能 `CRC32(源串的 UTF-32LE)`。**
   见 §2.2.1。用 UTF-8 逐字节扩展的写法对纯 ASCII 正确、对含中文标点/破折号的源串全错，表现为「477 条怎么改都不生效」。这是本项目历史上最大的一个坑。

## 1. 项目定位与支持矩阵

一句话：把《永恒之塔2》(AION 2) 国际服的**英文 / 日文**文本，替换成**简体 / 繁体**中文；只写本地化文本文件，可一键还原。

| 入口（下拉项） | 游戏内语言必须是 | 写入的目录 | 汉化结果 |
| --- | --- | --- | --- |
| 英文入口 | English | `en`、`en-US` | 简体 / 繁体 |
| 日文入口 | 日本語 | `ja`、`ja-JP` | 简体 / 繁体 |

四种组合 = 2 入口 × 2 文本。入口互斥，简繁可随时切换（同一入口换文本不删对方，因为写的是同一组目录）。

**当前版本**：`0.0.2`。**不做"一键切换入口"**（已被明确否掉），只做下拉选择 + 三个按钮。

## 2. 原理（必须理解这一段，否则改不动）

### 2.1 游戏怎么读文本

UE 在运行时按 culture 目录加载**松散** `.locres`：

```
<游戏根>\Engine\Content\Localization\Engine\Platforms\Windows\<culture>\Engine.locres
```

官方客户端**不自带**任何松散 locres（`pakchunk0` 里 0 个 locres 条目），所以磁盘上这四个位置是唯一来源：

```
en\Engine.locres      en-US\Engine.locres
ja\Engine.locres      ja-JP\Engine.locres
```

放进去 → 游戏读我们的中文；删掉 → 立即回落官方原文，无需备份。

### 2.2 locres 是"按 key + 源串哈希"匹配的

`Engine.locres` 的每条 entry 是：

```
(namespace, key, source_hash, string_index)
```

游戏用 `key` 匹配，并用 **`source_hash` = CRC32(官方源串的 UTF-32LE)** 校验译文对应的源串。所以：

- **译文可以随便改**（改 `string_index` 指向的字符串）；
- **`source_hash` 必须用该入口的官方源串算**，不能混用。

这就是本工具四份载荷的由来：

| 载荷 | 源串基准 | 结果 |
| --- | --- | --- |
| `payload\en\zh` / `en\zh-TW` | **英文**源串哈希 | 英文入口显示中文 |
| `payload\ja\zh` / `ja\zh-TW` | **日文**源串哈希 | 日文入口显示中文 |

英文与日文载荷的**译文完全相同**，只是 `source_hash` 不同，所以同文本下两个入口的文件大小一样，但哈希不同。

> 旧文档里"日文入口不读 locres"的实测，是把**英文哈希**的 locres 丢进 ja 目录做的，当然不生效。换成日文哈希就生效。

#### 2.2.1 非 ASCII 源串：477 条踩坑（必读，别再误判）

`source_hash` 必须用 **`CRC32(源串的 UTF-32LE 字节)`**。历史上的错误写法是：

```python
# ✗ 只对纯 ASCII 结果正确
zlib.crc32(b''.join(bytes([c, 0, 0, 0]) for c in s.encode('utf-8')))
# ✓ 正确
zlib.crc32(s.encode('utf-32-le'))
```

两者对纯 ASCII 串结果相同，所以绝大多数条目一直正常；一旦源串里有 `—`（破折号）、`’`（弯引号）、`※` 等非 ASCII 字符，UTF-8 多字节被逐字节扩展，哈希就算错，条目整体失效，界面继续显示英文/日文。

- 受影响规模：`en_src.json` 中含非 ASCII 的源串共 **477 条**，旧哈希全部算错。
- 典型症状：**登录页底部 4 行**（`String_UI_GLOBAL_SERVICE_SERVER_DELAY_TIME_NOTIE_body`）、**深渊 F_A**（`String_STR_Desc_Map_Abyss_F_A_body`，带破折号那段）、**深渊外围层 `Reshanta_D`**。全 ASCII 的深渊 F_C 一直正常，正好掩盖了问题。
- 结论：**不是"这 4 行 locres 覆盖不到、只能改 pak"，是哈希算错了。**
- 修复后 477 条全部命中，并已用游戏运行时内存里的英文原串交叉验证。
- 旧结论「底部 4 行无法汉化 / 只能走 pak」**已彻底作废**，不要再在任何地方引用。

> 商城/道具类偶尔还会有「散件名中文、套装名英文」：那是运行时拼接后的源串与 dat 原文不完全一致。处理办法见 `_内部工具\keyhunt\augment_hash_variants.py`（同时补「带 (Bound) / 不带 (Bound)」两套哈希）。商城**商品列表名**属商店表字面串，当前版本明确不在汉化范围（先不做）。

### 2.3 为什么入口互斥

游戏优先读 `en`（英文入口目录）。只要 `en` / `en-US` 有 locres，即使你选了日语，也会按 key 回退到英文表，导致「日文入口装了却没效果 / 串成英文」。因此：

- 装英文入口 → 先删 `ja`、`ja-JP`；
- 装日文入口 → 先删 `en`、`en-US`；
- 删了什么必须逐条写进日志（用户明确要求过）。

## 4. 载荷怎么生成（唯一入口：`build_release.py`）

> **先看这一句**：v0.0.2 的四份载荷由**一条命令**生成，不碰 pak、不解密、不扫内存。
> 如果你在别处看到"解 pak / 找容器密钥 / 内存扫密钥"的旧记录，那是已废弃的 v1.6.0 路线，跳过即可（见 §4.5）。

### 4.0 环境与路径

```
Windows + Python 3
pip install opencc pycryptodome lz4 blake3

本机路径约定：
  项目根   F:\《永恒之塔2》相关文件\1_文本汉化包
  仓库     F:\《永恒之塔2》相关文件\1_文本汉化包\Aion2-EN-CN
  内部工具 F:\《永恒之塔2》相关文件\1_文本汉化包\_内部工具
  生成脚本 F:\《永恒之塔2》相关文件\1_文本汉化包\_内部工具\keyhunt\build_release.py
  游戏根   F:\SteamLibrary\steamapps\common\Aion2
```

`build_release.py` 顶部写死了 `BASE` 绝对路径，**换机器必须先改 `BASE`**。脚本会从 `Aion2-EN-CN\tools` 导入 `_repro_standalone.py`（locres 写入原语）与 `aion2_l10n.py`（语料容器解码），从 `_内部工具` 导入 `_work_en` 下的语料。

### 4.1 输入资产（缺一不可）

| 资产 | 条数 | 作用 |
| --- | --- | --- |
| `_内部工具\_work_en\en_src.json` | 153,028 | 英文官方源串（11-18 基线，逐条校对过，作为主源） |
| `keyhunt\map_en_clean.json` | 153,238 | 11-26 从游戏内存转储提取的英文源串，用来补新 key（`setdefault`，不覆盖 `en_src.json`） |
| `keyhunt\map_ja.json` | 153,210 | 11-26 从日文内存转储提取的日文源串；值里带 `\x00`，脚本统一 `replace('\x00','')` |
| `keyhunt\oldja_hashes.json` | 153,029 | 旧日文载荷里已验证生效的 `key -> source_hash` 缓存 |
| `_内部工具\_work_en\out\plain_zh_v3.dat` | 153,029 | 简体译文语料（自定义容器，用 `ja-JP` 容器密钥解码） |
| `_内部工具\_work_en\out\plain_tw_v3.dat` | 153,029 | 繁体译文语料（同上） |
| `keyhunt\tr_new_final_zh.json` | 211 | 本次新增文本的**简体**译文（key → 简体） |

`oldja_hashes.json` 是 v0.0.2 新增的缓存：首次运行时从 v0.0.1 日文载荷解析生成，之后独立存在。
**它解决了一个坑**：日文源表只覆盖 153,210 条，但有 153,029 条旧条目的日文哈希已经验证生效；直接按新源表重算会让部分老条目丢哈希（源串在内存里被拼接/截断）。脚本对日文入口优先沿用 `OLDJA`，所以老条目 100% 保持命中。

写入位置：

| 组合 | 输出文件 |
| --- | --- |
| en + 简 | `_work_en\out\locres_zh_CN\en\Engine.locres` |
| en + 繁 | `_work_en\out\locres_zh_TW\en\Engine.locres` |

`build\build.ps1` 就是从这里取这四份文件打包。

### 4.3 脚本内部做了什么（按顺序）

1. **英文源**：读 `en_src.json`，再把 `map_en_clean.json` 里缺的 key `setdefault` 进来；最后强制 `String_UI_GLOBAL_SERVICE_SERVER_REGION_NAME_EU_body = 'Europe'`（服务器列表名，游戏里显示的就是 Europe）。
2. **日文源**：读 `map_ja.json`，值去掉 `\x00`。
3. **译文**：用 `aion2_l10n.decode_dat(..., 'ja-JP')` 解 `plain_zh_v3.dat` / `plain_tw_v3.dat`，得到 `key -> 简体/繁体` 字典。
4. **并入新译文**：遍历 `tr_new_final_zh.json`；简体直接写入，**繁体用 OpenCC `s2twp` 从简体转**（不要手写繁体，避免简繁不一致）。
5. **手工覆盖**：`OVR` 字典（当前只有 EU 服务器名 `欧洲` / `歐洲`）。
6. **分组**：`AION2` 命名空间放全部 key；另外 25 个候选命名空间各放 88 条登录/选服 key（`_repro_standalone.pick_login_keys`）。
7. **字符串池去重**：相同译文只存一份，写 `string_index`。
8. **写 locres**：`ver=1`，哈希用 `_repro_standalone.src_hash(s)`（即 `CRC32(s.encode('utf-32-le'))`）。
9. 日文入口额外传 `hash_override=OLDJA`：有日文源串就用源串算，没有就沿用旧哈希；两者都没有的 key 直接跳过（不写空哈希）。

### 4.4 校验（每次重建后必做）

1. 四份文件的**大小 + SHA256** 与 §3.1 逐项对齐（重建后先更新 §3.1）；
2. 结构校验（26 命名空间 / 155,438 entry / AION2 153,238）；
3. 进游戏实测四组合：英文入口简/繁、日文入口简/繁，各看登录页、选服、任务文本、深渊说明；
4. 跑 `build.ps1`，确认 `Aion2Diag.ps1` 的 4 组基准已被自动改写（日志会打印每份的 size 与前 16 位哈希）。

### 4.5 历史：为什么不再走 pak（只作背景，不要照做）

v1.6.0 的日文入口曾用 **pak 方案**：往 `ja-JP` / `zh` / `zh-TW` 写 `pakchunk*.pak`，把汉字塞进日文字形（"载体字"）。后果：

- 改 `L10NString.dat` 会让**整张表变问号**（改 1 条也一样）；
- 每次游戏大更都会**轮换容器密钥与头部掩码**，旧密钥直接失效，必须重新逆向；
- 写 `Binaries\Win64` 会导致启动报 `Failed to open descriptor file ... AION2.uproject` 或 `Some game files could not be loaded`。

**v0.0.1 起已全部废弃。** 现在只写松散 `Engine.locres`，四个文件，删掉即还原。
本文档不再提供任何 pak 密钥、掩码、代次表 —— 那些内容只会误导接手人（历史上已有 AI 照着旧文档折腾十几个小时跑不通）。

如果用户的机器上还有旧方案残留（启动报上面的错），处理见 §11.3。

### 4.6 游戏更新后：源表怎么重新抓

只有**游戏新增/改动了文本**时才需要这一步。日常改译文、重打包不需要。

前置：

1. 游戏已启动并过了登录，停在角色选择或游戏内（只停在公告界面时客户端还没加载文本表）；
2. 先「一键还原」，避免内存里混进中文覆盖；
3. 管理员权限运行（游戏进程受保护）。

```powershell
cd 'F:\《永恒之塔2》相关文件\1_文本汉化包\_内部工具\keyhunt'

# 1) 导出内存区域到 mem\（manifest.json + 各 region 文件）
python dump_mem.py            # 英文语言下运行 → mem\
python dump_mem.py mem_ja     # 日文语言下运行 → mem_ja\（改语言后完全退出重进）

# 2) 从转储里按节点结构提取 key -> 官方文本
python extract_map.py mem    map_en.json
python extract_map.py mem_ja map_ja.json

# 3) 清洗英文源（去尾部 NUL、修复内部 NUL 错位串）
python clean_map.py           # → map_en_clean.json
```

日文 `map_ja.json` 的值里可能带 `\x00`，`build_release.py` 会自动去掉，不用手工处理。

抓完源表后：把新文本的简体译文补进 `tr_new_final_zh.json`（见 §4.7），再跑 §4.2。

### 4.7 新增译文怎么加

- 只编辑 `keyhunt\tr_new_final_zh.json`：`{ "String_XXX_body": "简体译文", ... }`；
- **只写简体**，繁体由脚本用 OpenCC 自动生成；
- 不要动 `plain_zh_v3.dat` / `plain_tw_v3.dat`（历史语料容器，整批重做时才碰）；
- 不要在脚本里硬编码单条译文，统一走 `tr_new_final_zh.json` 或 `OVR`。

## 6. 界面规范（用户逐条盯过的，改动前务必看）

### 6.1 图形版（`Aion2CNTool.cs`）

窗口 `760 × 700`，DPI 由 `app.manifest` + 自写 `ScaleUi` 等比缩放（125% / 150% 不能错位）。

自上而下：

1. 顶部横幅：标题 + 版本 + 作者。**横幅下方留白，不要写任何提示句**。
2. 客户端检测区：勾选列表 + 重新扫描 + 手动选择。列表项**只显示来源 + 路径，绝不拼状态**（拼了就把路径挤掉）。
3. `选择汉化语言`（Label）+ **下拉框只有两项**：`英文入口` / `日文入口`，默认第 0 项。
4. 右侧 `当前状态：…` 实时显示 `英文入口 · 简体中文` 之类的完整状态。
5. `风险说明与操作` 框内顺序固定：
   - 说明框（4 段，顺序见下）
   - 阅读提示（橙色 → 完成变绿）
   - 勾选框（初始禁用）
   - 三个按钮：`一键应用简体` / `一键应用繁体` / `一键还原`
6. 实时日志区。

说明框 4 段（顺序不可调，最后一段是"读完正好滚到底"的收尾）：

```
1. 英文入口对应游戏语言 English，日文入口对应 日本語；两个入口互斥，安装时会先移除另一个入口的文件。
2. 执行汉化安装或还原前，请务必确保已完全退出 永恒之塔2 游戏进程。
3. 本工具完全免费开源，仅供交流学习，严禁任何形式的倒卖牟利。
4. 任何对游戏客户端的修改行为均可能存在不可预知的风险（包括但不限于游戏运行异常或账号封禁风险）。请使用者自行评估。
```

强制阅读机制（两版一致）：

- 说明框**必须能滚**：`ScrollBars = Vertical`（有滚动能力），再用 `ShowScrollBar(hwnd, SB_VERT, false)` **隐藏滚动条**；滚轮事件自己接管（每格 2 行，`WM_VSCROLL = 0x00B6`）。
  **不要用 `ScrollBars = None`** —— Windows 下它根本不支持滚动，字只是被裁掉。
- 判定「读到底」用**行**：最后一行进入可视区才算到底（不要用"最后一字是否可见"，短行会误判）。
- 到底后倒数 **3 秒**，才 `Enabled = true` 解锁勾选框；未勾选时两个"一键应用"按钮保持禁用。
- `一键还原` 永远可用，不需要勾选。

### 6.2 窗口版弹窗（`Show-Disclaimer`）

同样的 3 秒 + 滚到底逻辑。区别是弹窗**必须自己按 DPI 缩放全部控件**（WinForms 自动缩放只放大字体、不放大控件，125% 下会重叠 / 截断），按钮宽度按文字实测宽度撑开，横幅标签用 `AutoSize` 并给上下内边距（否则上沿被削 1~2 px）。

## 7. 构建与发布

### 7.1 构建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "F:\《永恒之塔2》相关文件\1_文本汉化包\Aion2-EN-CN\build\build.ps1"
```

`build.ps1` 做的事：

1. 检查 `csc.exe` 与四份载荷源；
2. 按实际载荷回写 `src\Aion2Diag.ps1` 的 4 组 Size/SHA256；
3. 清空并重建 `dist\永恒之塔2_国际服简繁汉化_v<版本>\`；
4. 用 `csc.exe` 编译 `src\Aion2CNTool.cs`（`/win32manifest:src\app.manifest`）；
5. 复制 ps1 / diag / 6 个 bat / 说明 txt / 四份载荷到 `payload\...`；
6. `Compress-Archive` 打 zip，打印大小与 SHA256。

底层编译命令（无需装 SDK）：

```powershell
& 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe' /nologo /target:winexe /optimize `
  /r:System.Windows.Forms.dll /r:System.Drawing.dll `
  "/win32manifest:...\src\app.manifest" `
  "/out:...\dist\...\1-图形版-双击启动.exe" "...\src\Aion2CNTool.cs"
```

> 编译器是 .NET Framework 4.0 的 C# 5：**不能用**表达式体属性、`?.`、`??`、字符串插值、`nameof`。

### 7.2 版本号要改的位置

| --- | --- |
| `version.json` | `"version": "0.0.2"`（Release 上线后再推，见 §7.3） |
| `build\build.ps1` | `$Version = '0.0.2'` |
| `src\Aion2CNTool.cs` | `currentVersion = "0.0.2"` 与 `AssemblyVersion("0.0.2.0")` / `AssemblyFileVersion` |

### 7.3 发布顺序（顺序错了用户点更新会 404）

```powershell
$repo = 'F:\《永恒之塔2》相关文件\1_文本汉化包\Aion2-EN-CN'

# 1) 生成载荷（若本次改了译文/源表）
cd 'F:\《永恒之塔2》相关文件\1_文本汉化包\_内部工具\keyhunt'; python build_release.py

# 2) 构建
powershell -NoProfile -ExecutionPolicy Bypass -File "$repo\build\build.ps1"

# 3) 提交源码（载荷与 dist 已被 .gitignore 忽略）
git -C $repo add -A
git -C $repo commit -m "release: v0.0.2 ..."
git -C $repo push origin main

# 4) 上传前先把 zip 复制成 ASCII 文件名（中文资产名会被 GitHub 改写成 2_._xxx.zip）
Copy-Item "$repo\dist\永恒之塔2_国际服简繁汉化_v0.0.2.zip" "$env:TEMP\Aion2-Global-CN-v0.0.2.zip"

# 5) 建 Release（gh 用用户身份）
gh auth switch --user duoluoyuji
gh release create v0.0.2 "$env:TEMP\Aion2-Global-CN-v0.0.2.zip" `
  --repo duoluoyuji/Aion2-Global-CN --title "v0.0.2 国际服简繁汉化" --notes-file <说明文件>

# 6) 已存在版本时替换资产
gh release upload v0.0.2 "$env:TEMP\Aion2-Global-CN-v0.0.2.zip" --repo duoluoyuji/Aion2-Global-CN --clobber

# 7) 最后才改 version.json 并推送（先有 Release，再放版本号）
```

**注意**：`gh` 必须用用户身份（`gh auth switch --user duoluoyuji`）。GitHub App 集成令牌**没有**建仓库 / 建 Release 的权限（`Resource not accessible by integration`）。

### 7.4 更新检查的两个必须项

1. **TLS 1.2**：.NET 4.0 默认只协商 TLS 1.0，GitHub 只收 1.2，不设会静默失败。
   - C#：`ServicePointManager.SecurityProtocol = (SecurityProtocolType)3072;`
   - PS：`[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]3072`
2. **镜像**：大陆直连 raw 不通，代码是「主地址失败 2 秒后切 `https://gh-proxy.com/<原始 raw 地址>`」，全失败则静默跳过（不影响汉化）。

更新检查地址（共 4 处：cs 两个 + ps1 两个）：

```
https://raw.githubusercontent.com/duoluoyuji/Aion2-Global-CN/main/version.json
https://gh-proxy.com/https://raw.githubusercontent.com/duoluoyuji/Aion2-Global-CN/main/version.json
```

只接受**同主版本号**的更高版本（`r.Major == l.Major && r > l`），避免旧仓库 v2.x 的版本号把 v0.0.x 顶成"有新版"。

## 8. 客户端识别、状态与语言

### 8.1 目录合法性

`<root>\Aion2\Content\Paks` 存在即合法（大小写不敏感）。
扫描来源：Steam（`appmanifest_3393110.acf` 正式服 / `4972320.acf` 测试服、`HKCU\Software\Valve\Steam`、各盘 `SteamLibrary\steamapps\common\Aion2`）+ PURPLE（`plaync` BaseDir、卸载列表、12 条默认路径）。多客户端用勾选列表选择。

### 8.2 状态枚举

```
官方原版                              ← 四个文件都不存在
英文入口 · 简体中文 / 繁体中文        ← en/en-US 两个文件哈希都等于对应载荷
日文入口 · 简体中文 / 繁体中文        ← ja/ja-JP 两个文件哈希都等于对应载荷
异常：两个入口的文件同时存在          ← en 与 ja 各有文件（应提示还原）

目录无效                              ← 结构不合法
```

### 8.3 语言一致性校验

读 `%LOCALAPPDATA%\Aion2\Saved*\Config\Windows\Engine.ini` 的 `[Internationalization] Culture=`：

```
en → English (en-US)
ja → 日本語 (ja-JP)
```

与所选入口不符时**只弹 YesNo 提示**（"请先把游戏内语言改为 xxx"），用户点否就终止，**绝不修改 ini**。读不到配置时跳过校验（游戏未启动过）。

### 8.4 冲突进程

`Aion2`、`Aion2-Win64-Shipping`、`NCLauncher`、`NCLauncher2`、`Purple`、`PurpleApp`。检测到就循环弹窗，等用户退出后点「重试」。

## 9. 回归校验清单（每次发版前必须全过）

### 9.1 自动化（文件层，用假客户端目录 `<tmp>\Aion2\Content\Paks\L10N`）

1. 四份载荷尺寸 + SHA256 与 §3.1 逐项一致（8 项）；
2. 空目录 → `官方原版`；
3. 装 `en/zh` → 状态 `英文入口 · 简体中文`，`en`/`en-US` 两个文件 16,105,338，`ja`/`ja-JP` 不存在；
4. 切 `ja/zh-TW` → 自动删除 `en`/`en-US`（日志两条 `[移除]`），`ja`/`ja-JP` 16,105,454，状态 `日文入口 · 繁体中文`；
5. 切 `ja/zh` → `日文入口 · 简体中文`；
6. 切 `en/zh-TW` → `英文入口 · 繁体中文`；
7. 人为造两组并存 → `异常：两个入口的文件同时存在`；
8. 还原 → 删除 4 个文件，状态回 `官方原版`；
9. 6 个 bat 全为 CRLF、ps1 带 BOM、exe 与说明存在。

### 9.2 人工（真机）

1. 图形版在 100% / 125% / 150% 三档缩放截图：下拉、状态、说明框、勾选框、三个按钮、日志均不重叠、不截断；
2. 说明框能滚轮滚动、无可见滚动条、滚到底倒数 3 秒后解锁；
3. 窗口版 4 个安装 bat + 还原 bat 能跑通（退出码 0，无 9009）；
4. 装完进游戏确认中文；还原后确认回落官方原文；
5. 跑 `4-出问题点这个-生成诊断.bat`，报告里应显示当前状态与语言是否匹配。

### 9.3 诊断脚本的基准

`Aion2Diag.ps1` 里写死了 4 份载荷的尺寸与 SHA256、`$LOC_CULTURES = @('en','en-US','ja','ja-JP')`、`pkgNeeded`（bat 名 + 4 个载荷路径）。**载荷或包结构一变，这里必须同步**。
其中 4 组尺寸 / SHA256 已由 `build.ps1` 自动回写；`pkgNeeded` 与目录结构仍是手工项。

## 11. 排障手册

### 11.1 装完还是英文 / 日文

入口选错。英文入口要求游戏语言 English，日文入口要求 日本語。改语言后要**完全退出游戏和启动器**再进。工具不会代改语言。

### 11.2 日志出现 `[移除]` 是正常的

装另一入口时必然先删旧入口，这是设计行为，不是报错。

### 11.3 启动报 `Failed to open descriptor file ../../../Aion2/AION2.uproject` / `Some game files could not be loaded`

这是**旧 pak 方案（v1.6.0）残留**，与本工具无关。旧方案往这些位置写过 pak：

```
ja-JP\pakchunk0-Windows.pak
zh\pakchunk503000-Windows_0_P.pak
zh-TW\pakchunk503000-Windows_0_P.pak
```

处理顺序：

1. 跑旧包的还原 bat（`3-窗口版-还原官方日文.bat`）；
2. Steam / PURPLE **校验游戏文件完整性**（只补缺失，不删多余）；
3. 仍不行 → 删掉整个 `<root>\Aion2\Binaries\Win64`，再校验一次（实测有效）；
4. 检查杀软隔离区，恢复被隔离的 dll 或加白；
5. 之后改用本工具（只写 locres，不碰 pak / Binaries）。

### 11.4 提示"安装包不完整"

`payload\<入口>\<文本>\Engine.locres` 缺失或小于 1 MB。多为在压缩软件里直接双击运行、或杀软拦截。完整解压后重试。

### 11.5 写入失败 / 文件被占用

游戏或启动器还在后台；杀软实时防护锁文件。完全退出后重试，必要时以管理员运行。

### 11.6 控制台出现乱码报错行

通常是 ps1 里调用了未定义的函数（PowerShell 的 `CommandNotFound` 中文消息在 GBK 控制台显示成乱码）。用 AST 静态检查一遍函数定义与调用是否对齐。

## 12. 踩过的坑

1. **bat 是 LF** → cmd 逐行错位，报 `'cal'`、`'2'`、`'-NoProfile'`、错误码 9009。必须 GBK + CRLF。
2. **ps1 无 BOM** → PowerShell 5 按 ANSI 读，中文乱码且 `$变量` 被吞（表现为 `foreach ( in ...)`）。
3. **同一 GroupBox 里的多个 RadioButton** → WinForms 自动成一组，点语言就把入口取消。改成单个 `ComboBox`。
4. **`ScrollBars = None` 的多行 TextBox 不能滚** → 必须 `Vertical` + `ShowScrollBar` 隐藏。
5. **「最后一字可见」判定到底** → 短行会误判，改按行判断。
6. **`AutoSize = false` + 手算高度** → 字体度量稍差就被裁 1~2 px（"即将执行"截断）。标签一律 `AutoSize = true`，面板按子控件实测底部重排。
7. **WinForms 自动 DPI 缩放只放大字体** → 控件不放大，125% 下重叠 / 大片空白。必须自己按 DPI 缩放控件矩形。
8. **列表项拼接完整状态** → 路径被挤出可视区。列表只放路径，状态放右侧。
9. **删掉 `Stop-ConflictProcesses` 函数** → 调用时报错、控制台乱码。删函数前先搜调用点。
10. **Release body 用 `\n` 拼字符串** → 换行丢失，整段被 Markdown 当成一个一级标题（字巨大、挤成一团）。写 body 用 here-string。
11. **中文文件名上传 GitHub 资产** → 被改写成 `2_._v0.0.2.zip`。上传前先复制成 ASCII 文件名。
12. **GitHub App 令牌建仓库** → 403 `Resource not accessible by integration`。用 `gh` + 用户身份。
13. **`raw.githubusercontent.com` 缓存** → 改完 README 用 raw 校验可能还是旧内容，用 API `contents` 或网页刷新确认。
14. **旧仓库链接残留** → 换仓库后必须全量搜 `Aion2-EN-CN` / `Aion2-Steam-CN`。
15. **`source_hash` 用 UTF-8 算** → 纯 ASCII 看不出问题，含 `—`/`’`/`※` 的 477 条哈希全错，表现为登录页 4 行、深渊 F_A、Reshanta_D 回落原文。必须 `CRC32(s.encode('utf-32-le'))`。旧结论"这 4 行做不到、只能改 pak"是误判，已作废。
16. **日文入口直接按新源表重算哈希** → 部分旧条目源串在内存里被拼接/截断，算出来的哈希与游戏不匹配，表现为「日文入口部分文本回退日文」。必须沿用 `oldja_hashes.json` 里已验证的哈希（脚本已处理）。
17. **找"日文模板 locres"** → 不存在。日文源串只能从游戏内存转储提取（§4.6）。

## 13. 术语

| 词 | 含义 |
| --- | --- |
| locres | Localization Resource，本地化字符串表文件（不是"本地资源"） |
| culture | 语言目录名：`en`、`en-US`、`ja`、`ja-JP` |
| namespace | locres 内的命名空间；本工具主用 `AION2` + 25 个候选 |
| source_hash | 官方源串（英文或日文）的 CRC32(UTF-32LE)，游戏匹配译文用 |
| 载荷 | `payload` 下的四个 `Engine.locres`，安装时复制到游戏目录 |
| 入口 | 英文入口（English）或日文入口（日本語），决定写哪组 culture 目录 |
| 载体字 | v1.6.0 pak 方案用日文字形拼汉字的旧技术，**已废弃**，本工具不使用 |

## 14. 接手五分钟自检

1. 读 §0、§2，理解"只写 locres + 入口互斥 + 哈希分入口 + 哈希必须 UTF-32LE"。
2. 跑 `python build_release.py`（§4.2），四份载荷的 size / sha256 应与 §3.1 一致 —— 这说明你的环境、源表、译文都对。
3. 跑一次构建（§7.1），确认 `dist` 生成、zip SHA256 打印出来。
4. 跑 §9.1 的文件层验证（假目录部署），四组合 + 还原全过。
5. 打开 https://github.com/duoluoyuji/Aion2-Global-CN ，比对 Release 资产大小 / SHA256 与本地 zip。
6. 打开图形版，确认：下拉两项、三按钮、说明 4 段顺序、滚到底 3 秒解锁、日志正常。
7. 跑诊断 bat，确认能识别本机客户端状态与语言。
8. 到这一步你已经可以独立维护并发布 v0.0.x 了。**任何让你去解 pak 的念头，都是看错了旧文档。**
