## 0. 六条红线（违反任何一条都会让用户游戏起不来或汉化失效）

1. **只写 `Engine.locres`，绝对不要碰任何 `pak`。**
   改封在 pak 里的 `L10NString.dat` 会让整张表变问号（改 1 条和改 3 条一样）。已复现多次。
2. **两个入口必须物理互斥。**
   `en` / `en-US` 的 locres 存在时，会按 key 回退覆盖 `ja` / `ja-JP`。所以部署任一入口前，**先删掉另一入口的全部文件**，并在日志里逐条写明删了什么。
3. **不要改 `Engine.ini` 的 `Culture`。**
   工具只提示"入口要和游戏内语言一致"，绝不代改游戏设置。历史上的 `Ensure-JapaneseCulture` 已整段删除，别加回来。
4. **删文件即还原，不要做备份、不要恢复备份。**
   官方客户端不自带松散 locres，删掉四个文件立即回落官方原版。
5. **`.bat` 必须 GBK(936) + CRLF；`.ps1` 必须 UTF-8 with BOM。**
   LF 的 bat 会让 cmd 解析错乱（报 `'cal'` / `'-NoProfile'`，错误码 9009）；无 BOM 的 ps1 会让 PowerShell 5 按 ANSI 读中文，界面乱码且变量被吞。
6. **载荷哈希与诊断脚本里写死的基准必须同步。**
   重新生成载荷后，`Aion2Diag.ps1` 顶部的 4 组尺寸 / SHA256 要一起改，否则诊断会把正常安装判成"未知汉化文件"。

## 1. 项目定位与支持矩阵

一句话：把《永恒之塔2》(AION 2) 国际服的**英文 / 日文**文本，替换成**简体 / 繁体**中文；只写本地化文本文件，可一键还原。

| 入口（下拉项） | 游戏内语言必须是 | 写入的目录 | 汉化结果 |
| --- | --- | --- | --- |
| 英文入口 | English | `en`、`en-US` | 简体 / 繁体 |
| 日文入口 | 日本語 | `ja`、`ja-JP` | 简体 / 繁体 |

四种组合 = 2 入口 × 2 文本。入口互斥，简繁可随时切换（同一入口换文本不删对方，因为写的是同一组目录）。

**当前版本**：`0.0.1`。**不做"一键切换入口"**（已被明确否掉），只做下拉选择 + 三个按钮。

## 2. 原理（必须理解这一段，否则改不动）

### 2.1 游戏怎么读文本

UE 在运行时按 culture 目录加载**松散** `.locres`：

```
<游戏根>\Engine\Content\Localization\Engine\Platforms\Windows\<culture>\Engine.locres
```

官方客户端**不自带**任何松散 locres（`pakchunk0` 里 0 个 locres 条目），所以磁盘上这四个位置是唯一来源：

```
en\Engine.locres      en-US\Engine.locres
ja\Engine.locres      ja-JP\Engine.locres
```

放进去 → 游戏读我们的中文；删掉 → 立即回落官方原文，无需备份。

### 2.2 locres 是"按 key + 源串哈希"匹配的

`Engine.locres` 的每条 entry 是：

```
(namespace, key, source_hash, string_index)
```

游戏用 `key` 匹配，并用 **`source_hash` = CRC32(官方源串的 UTF-32LE)** 校验译文对应的源串。所以：

- **译文可以随便改**（改 `string_index` 指向的字符串）；
- **`source_hash` 必须用该入口的官方源串算**，不能混用。

这就是本工具四份载荷的由来：

| 载荷 | 源串基准 | 结果 |
| --- | --- | --- |
| `payload\en\zh` / `en\zh-TW` | **英文**源串哈希 | 英文入口显示中文 |
| `payload\ja\zh` / `ja\zh-TW` | **日文**源串哈希 | 日文入口显示中文 |

英文与日文的载荷**译文完全相同**，只是 `source_hash` 不同，所以文件大小一样（16,088,441 / 16,088,557 B），但哈希不同。

> 旧文档里"日文入口不读 locres"的实测，是把**英文哈希**的 locres 丢进 ja 目录做的，当然不生效。换成日文哈希就生效 —— 这正是 `_build_ja_entry.py` 做的事。

### 2.3 为什么入口互斥

游戏优先读 `en`（英文入口目录）。只要 `en` / `en-US` 有 locres，即使你选了日语，也会按 key 回退到英文表，导致「日文入口装了却没效果 / 串成英文」。因此：

- 装英文入口 → 先删 `ja`、`ja-JP`；
- 装日文入口 → 先删 `en`、`en-US`；
- 删了什么必须逐条写进日志（用户明确要求过）。

### 3.2 结构（2026-11-19 实测解析）

四份都一样：

```

  └ 'AION2' 命名空间 153,029 条
```

## 4. 载荷怎么来的（重建流程）

### 4.0 环境

```
Windows + Python 3（pip install pycryptodome lz4 blake3）
本机路径约定：
  项目根   F:\《永恒之塔2》相关文件\1_文本汉化包
  仓库     F:\《永恒之塔2》相关文件\1_文本汉化包\Aion2-EN-CN
  内部工具 F:\《永恒之塔2》相关文件\1_文本汉化包\_内部工具
  游戏根   F:\SteamLibrary\steamapps\common\Aion2
```

脚本里 `GAME` / `BASE` / `TEMPLATE` 都是写死的绝对路径，**换机器必须先改**。

### 4.1 英文入口两份（en\zh、en\zh-TW）

来源脚本：`_内部工具\_repro_standalone.py`

输入：
- 官方 pak：`Aion2\Content\Paks\L10N\Text\en-US\pakchunk502000-Windows_0_P.pak`
- 译文表：`_内部工具\_work_en\out\plain_zh_v3.dat` / `plain_tw_v3.dat`（明文简 / 繁，键 → 中文）

```powershell
cd 'F:\《永恒之塔2》相关文件\1_文本汉化包\_内部工具'
python _repro_standalone.py
```

输出 `_out_repro\{zh,zh-TW}\Engine.locres`。然后铺到成品载荷位置：

```
_out_repro\zh\Engine.locres    → _work_en\out\locres_zh_CN\en\Engine.locres
_out_repro\zh-TW\Engine.locres → _work_en\out\locres_zh_TW\en\Engine.locres
```

> `_repro_standalone.py` 里的 `RELEASE` 常量原本指向旧的 v2.1.2 目录（只用于打印 IDENTICAL/DIFF 对比），改版时记得同步，或直接忽略该行输出。

### 4.2 日文入口两份（ja\zh、ja\zh-TW）

来源脚本：`_内部工具\_build_ja_entry.py`

原理：**以游戏里已验证生效的 `ja\Engine.locres` 为模板**，完整保留模板的 `(namespace, key, source_hash)`，只把译文换成我们的简 / 繁中文。这样哈希天然是日文源串的。

```powershell
cd 'F:\《永恒之塔2》相关文件\1_文本汉化包\_内部工具'
python _build_ja_entry.py
```

脚本顶部常量：

```python
PLAIN_ZH  = ...\_work_en\out\plain_zh_v3.dat
PLAIN_TW  = ...\_work_en\out\plain_tw_v3.dat
TEMPLATE  = F:\SteamLibrary\steamapps\common\Aion2\Engine\Content\Localization\Engine\Platforms\Windows\ja\Engine.locres
OUTDIR    = ...\_内部工具\_out_entry\ja
```

输出：

```
_out_entry\ja\zh\Engine.locres
_out_entry\ja\zh-TW\Engine.locres
```

注意事项：
- **模板必须存在**。本机已留档一份，路径 `_内部工具\_template_ja\Engine.locres`（16,088,557 B，SHA256 `1C9AD7F8…943771`），换机器重建时把它放回游戏 `ja\Engine.locres` 即可。若留档丢失，只能先让旧日文方案装一次来生成模板，或向作者索取。
- 脚本会打印"译文缺失 N"—— 缺失的条目保留日文原文，属正常。
- 重建后必须核对 §3.1 的哈希；不一致先查 `PLAIN_*` 是否指到了旧表。

## 6. 界面规范（用户逐条盯过的，改动前务必看）

### 6.1 图形版（`Aion2CNTool.cs`）

窗口 `760 × 700`，DPI 由 `app.manifest` + 自写 `ScaleUi` 等比缩放（125% / 150% 不能错位）。

自上而下：

1. 顶部横幅：标题 + 版本 + 作者。**横幅下方留白，不要写任何提示句**。
2. 客户端检测区：勾选列表 + 重新扫描 + 手动选择。列表项**只显示来源 + 路径，绝不拼状态**（拼了就把路径挤掉）。
3. `选择汉化语言`（Label）+ **下拉框只有两项**：`英文入口` / `日文入口`，默认第 0 项。
4. 右侧 `当前状态：…` 实时显示 `英文入口 · 简体中文` 之类的完整状态。
5. `风险说明与操作` 框内顺序固定：
   - 说明框（4 段，顺序见下）
   - 阅读提示（橙色 → 完成变绿）
   - 勾选框（初始禁用）
   - 三个按钮：`一键应用简体` / `一键应用繁体` / `一键还原`
6. 实时日志区。

说明框 4 段（顺序不可调，最后一段是"读完正好滚到底"的收尾）：

```
1. 英文入口对应游戏语言 English，日文入口对应 日本語；两个入口互斥，安装时会先移除另一个入口的文件。
2. 执行汉化安装或还原前，请务必确保已完全退出 永恒之塔2 游戏进程。
3. 本工具完全免费开源，仅供交流学习，严禁任何形式的倒卖牟利。
4. 任何对游戏客户端的修改行为均可能存在不可预知的风险（包括但不限于游戏运行异常或账号封禁风险）。请使用者自行评估。
```

强制阅读机制（两版一致）：

- 说明框**必须能滚**：`ScrollBars = Vertical`（有滚动能力），再用 `ShowScrollBar(hwnd, SB_VERT, false)` **隐藏滚动条**；滚轮事件自己接管（每格 2 行，`WM_VSCROLL = 0x00B6`）。
  **不要用 `ScrollBars = None`** —— Windows 下它根本不支持滚动，字只是被裁掉。
- 判定「读到底」用**行**：最后一行进入可视区才算到底（不要用"最后一字是否可见"，短行会误判）。
- 到底后倒数 **3 秒**，才 `Enabled = true` 解锁勾选框；未勾选时两个"一键应用"按钮保持禁用。
- `一键还原` 永远可用，不需要勾选。

### 6.2 窗口版弹窗（`Show-Disclaimer`）

同样的 3 秒 + 滚到底逻辑。区别是弹窗**必须自己按 DPI 缩放全部控件**（WinForms 自动缩放只放大字体、不放大控件，125% 下会重叠 / 截断），按钮宽度按文字实测宽度撑开，横幅标签用 `AutoSize` 并给上下内边距（否则上沿被削 1~2 px）。

## 7. 构建与发布

### 7.1 构建

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "F:\《永恒之塔2》相关文件\1_文本汉化包\Aion2-EN-CN\build\build.ps1"
```

`build.ps1` 做的事：

1. 检查 `csc.exe` 与四份载荷源；
2. 清空并重建 `dist\永恒之塔2_国际服简繁汉化_v0.0.1\`；
3. 用 `csc.exe` 编译 `src\Aion2CNTool.cs`（`/win32manifest:src\app.manifest`）；
4. 复制 ps1 / diag / 6 个 bat / 说明 txt / 四份载荷到 `payload\...`；
5. `Compress-Archive` 打 zip，打印大小与 SHA256。

底层编译命令（无需装 SDK）：

```powershell
& 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe' /nologo /target:winexe /optimize `
  /r:System.Windows.Forms.dll /r:System.Drawing.dll `
  "/win32manifest:...\src\app.manifest" `
  "/out:...\dist\...\1-图形版-双击启动.exe" "...\src\Aion2CNTool.cs"
```

> 编译器是 .NET Framework 4.0 的 C# 5：**不能用**表达式体属性、`?.`、`??`、字符串插值、`nameof`。

### 7.2 版本号要改 4 处

| 位置 | 值 |
| --- | --- |
| `version.json` | `"version": "0.0.1"` |
| `build\build.ps1` | `$Version = '0.0.1'` |
| `src\Aion2CNTool.cs` | `currentVersion = "0.0.1"` 与 `AssemblyVersion("0.0.1.0")` |
| `src\Aion2CNTool.ps1` | `$CurrentVersion = '0.0.1'` |

### 7.3 发布顺序（顺序错了用户点更新会 404）

```powershell
$repo = 'F:\《永恒之塔2》相关文件\1_文本汉化包\Aion2-EN-CN'

# 1) 构建
powershell -NoProfile -ExecutionPolicy Bypass -File "$repo\build\build.ps1"

# 2) 提交源码（载荷与 dist 已被 .gitignore 忽略）
git -C $repo add -A
git -C $repo commit -m "feat: ..."
git -C $repo push origin main

# 3) 建 Release 并上传 zip（资产名用英文，中文名会被 GitHub 接口弄成 2_._... 这种）
gh release create v0.0.1 "$repo\dist\永恒之塔2_国际服简繁汉化_v0.0.1.zip" `
  --repo duoluoyuji/Aion2-Global-CN --title "v0.0.1 国际服简繁汉化" --notes-file <说明文件>

# 4) 已存在版本时替换资产
gh release upload v0.0.1 <zip> --repo duoluoyuji/Aion2-Global-CN --clobber

# 5) 最后才改 version.json 并推送（先有 Release，再放版本号）
```

**注意**：`gh` 必须用用户身份（`gh auth switch --user duoluoyuji`）。GitHub App 集成令牌**没有**建仓库 / 建 Release 的权限（`Resource not accessible by integration`）。

### 7.4 更新检查的两个必须项

1. **TLS 1.2**：.NET 4.0 默认只协商 TLS 1.0，GitHub 只收 1.2，不设会静默失败。
   - C#：`ServicePointManager.SecurityProtocol = (SecurityProtocolType)3072;`
   - PS：`[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]3072`
2. **镜像**：大陆直连 raw 不通，代码是「主地址失败 2 秒后切 `https://gh-proxy.com/<原始 raw 地址>`」，全失败则静默跳过（不影响汉化）。

更新检查地址（共 3 处：cs 两个 + ps1 两个）：

```
https://raw.githubusercontent.com/duoluoyuji/Aion2-Global-CN/main/version.json
https://gh-proxy.com/https://raw.githubusercontent.com/duoluoyuji/Aion2-Global-CN/main/version.json
```

只接受**同主版本号**的更高版本（`r.Major == l.Major && r > l`），避免旧仓库 v2.x 的版本号把 v0.0.1 顶成"有新版"。

### 7.5 换仓库名要改的地址（搜索 `Aion2-Global-CN`）

| 文件 | 位置 |
| --- | --- |
| `src\Aion2CNTool.ps1` | 第 4 行注释、横幅「开源主页」、`$RemoteVersionUrl`、`$FallbackVersionUrl`、还原/更新后的 releases 链接 |
| `src\Aion2CNTool.cs` | 更新检查两个地址、releases 跳转 |

## 8. 客户端识别、状态与语言

### 8.1 目录合法性

`<root>\Aion2\Content\Paks` 存在即合法（大小写不敏感）。
扫描来源：Steam（`appmanifest_3393110.acf` 正式服 / `4972320.acf` 测试服、`HKCU\Software\Valve\Steam`、各盘 `SteamLibrary\steamapps\common\Aion2`）+ PURPLE（`plaync` BaseDir、卸载列表、12 条默认路径）。多客户端用勾选列表选择。

### 8.2 状态枚举

```
官方原版                              ← 四个文件都不存在
英文入口 · 简体中文 / 繁体中文        ← en/en-US 两个文件哈希都等于对应载荷
日文入口 · 简体中文 / 繁体中文        ← ja/ja-JP 两个文件哈希都等于对应载荷
异常：两个入口的文件同时存在          ← en 与 ja 各有文件（应提示还原）
未知汉化文件                          ← 存在但不匹配任何载荷（旧方案残留 / 手工装）
目录无效                              ← 结构不合法
```

### 8.3 语言一致性校验

读 `%LOCALAPPDATA%\Aion2\Saved*\Config\Windows\Engine.ini` 的 `[Internationalization] Culture=`：

```
en → English (en-US)
ja → 日本語 (ja-JP)
```

与所选入口不符时**只弹 YesNo 提示**（"请先把游戏内语言改为 xxx"），用户点否就终止，**绝不修改 ini**。读不到配置时跳过校验（游戏未启动过）。

### 8.4 冲突进程

`Aion2`、`Aion2-Win64-Shipping`、`NCLauncher`、`NCLauncher2`、`Purple`、`PurpleApp`。检测到就循环弹窗，等用户退出后点「重试」。

## 9. 回归校验清单（每次发版前必须全过）

### 9.1 自动化（本次 v0.0.1 实测 32 项全 PASS）

用假客户端目录（`<tmp>\Aion2\Content\Paks\L10N`）跑文件层流程：

1. 四份载荷尺寸 + SHA256 与 §3.1 逐项一致（8 项）；
2. 空目录 → `官方原版`；
3. 装 `en/zh` → 状态 `英文入口 · 简体中文`，`en`/`en-US` 两个文件大小 16,088,441，`ja`/`ja-JP` 不存在；
4. 切 `ja/zh-TW` → 自动删除 `en`/`en-US`（日志两条 `[移除]`），`ja`/`ja-JP` 16,088,557，状态 `日文入口 · 繁体中文`；
5. 切 `ja/zh` → `日文入口 · 简体中文`；
6. 切 `en/zh-TW` → `英文入口 · 繁体中文`；
7. 人为造两组并存 → `异常：两个入口的文件同时存在`；
8. 还原 → 删除 4 个文件，状态回 `官方原版`；
9. 6 个 bat 全为 CRLF、ps1 带 BOM、exe 与说明存在。

### 9.2 人工（真机）

1. 图形版在 100% / 125% / 150% 三档缩放截图：下拉、状态、说明框、勾选框、三个按钮、日志均不重叠、不截断；
2. 说明框能滚轮滚动、无可见滚动条、滚到底倒数 3 秒后解锁；
3. 窗口版 4 个安装 bat + 还原 bat 能跑通（退出码 0，无 9009）；
4. 装完进游戏确认中文；还原后确认回落官方原文；
5. 跑 `4-出问题点这个-生成诊断.bat`，报告里应显示当前状态与语言是否匹配。

### 9.3 诊断脚本的基准

`Aion2Diag.ps1` 里写死了 4 份载荷的尺寸与 SHA256、`$LOC_CULTURES = @('en','en-US','ja','ja-JP')`、`pkgNeeded`（新 bat 名 + 4 个载荷路径）。**载荷或包结构一变，这里必须同步**。

## 11. 排障手册（这两天真实用户案例）

### 11.1 装完还是英文 / 日文

入口选错。英文入口要求游戏语言 English，日文入口要求 日本語。改语言后要**完全退出游戏和启动器**再进。工具不会代改语言。

### 11.2 日志出现 `[移除]` 是正常的

装另一入口时必然先删旧入口，这是设计行为，不是报错。

### 11.3 启动报 `Failed to open descriptor file ../../../Aion2/AION2.uproject` / `Some game files could not be loaded`

这是**旧 pak 方案残留**，与本工具无关。旧方案往这些位置写了 pak：

```
ja-JP\pakchunk0-Windows.pak
zh\pakchunk503000-Windows_0_P.pak
zh-TW\pakchunk503000-Windows_0_P.pak
```

处理顺序：

1. 跑旧包的还原 bat（`3-窗口版-还原官方日文.bat`）；
2. Steam / PURPLE **校验游戏文件完整性**（只补缺失，不删多余）；
3. 仍不行 → 删掉整个 `<root>\Aion2\Binaries\Win64`，再校验一次（实测有效：卸载重装都无效时，这一步能恢复）；
4. 检查杀软隔离区，恢复被隔离的 dll 或加白；
5. 之后改用本工具（只写 locres，不碰 pak / Binaries）。

### 11.4 提示"安装包不完整"

`payload\<入口>\<文本>\Engine.locres` 缺失或小于 1 MB。多为在压缩软件里直接双击运行、或杀软拦截。完整解压后重试。

### 11.5 写入失败 / 文件被占用

游戏或启动器还在后台；杀软实时防护锁文件。完全退出后重试，必要时以管理员运行。

### 11.6 控制台出现乱码报错行

通常是 ps1 里调用了未定义的函数（PowerShell 的 `CommandNotFound` 中文消息在 GBK 控制台显示成乱码）。用 AST 静态检查一遍函数定义与调用是否对齐。

## 12. 踩过的坑（只列这两天踩的）

1. **bat 是 LF** → cmd 逐行错位，报 `'cal'`、`'2'`、`'-NoProfile'`、错误码 9009。必须 GBK + CRLF。
2. **ps1 无 BOM** → PowerShell 5 按 ANSI 读，中文乱码且 `$变量` 被吞（表现为 `foreach ( in ...)`）。
3. **同一 GroupBox 里的多个 RadioButton** → WinForms 自动成一组，点语言就把入口取消。改成单个 `ComboBox`。
4. **`ScrollBars = None` 的多行 TextBox 不能滚** → 必须 `Vertical` + `ShowScrollBar` 隐藏。
5. **「最后一字可见」判定到底** → 短行会误判，改按行判断。
6. **`AutoSize = false` + 手算高度** → 字体度量稍差就被裁 1~2 px（"即将执行"截断）。标签一律 `AutoSize = true`，面板按子控件实测底部重排。
7. **WinForms 自动 DPI 缩放只放大字体** → 控件不放大，125% 下重叠 / 大片空白。必须自己按 DPI 缩放控件矩形。
8. **列表项拼接完整状态** → 路径被挤出可视区。列表只放路径，状态放右侧。
9. **删掉 `Stop-ConflictProcesses` 函数** → 调用时报错、控制台乱码。删函数前先搜调用点。
10. **Release body 用 `\n` 拼字符串** → 换行丢失，整段被 Markdown 当成一个一级标题（字巨大、挤成一团）。写 body 用 here-string。
11. **中文文件名上传 GitHub 资产** → 被改写成 `2_._v0.0.1.zip`。资产名用英文。
12. **GitHub App 令牌建仓库** → 403 `Resource not accessible by integration`。用 `gh` + 用户身份。
13. **`raw.githubusercontent.com` 缓存** → 改完 README 用 raw 校验可能还是旧内容，用 API `contents` 或网页刷新确认。
14. **旧仓库链接残留** → 换仓库后必须全量搜 `Aion2-EN-CN` / `Aion2-Steam-CN`，共 9 处以上。

## 13. 术语

| 词 | 含义 |
| --- | --- |
| locres | Localization Resource，本地化字符串表文件（不是"本地资源"） |
| culture | 语言目录名：`en`、`en-US`、`ja`、`ja-JP` |
| namespace | locres 内的命名空间；本工具主用 `AION2` + 25 个候选 |
| source_hash | 官方源串（英文或日文）的 CRC32(UTF-32LE)，游戏匹配译文用 |
| 载荷 | `payload` 下的四个 `Engine.locres`，安装时复制到游戏目录 |
| 入口 | 英文入口（English）或日文入口（日本語），决定写哪组 culture 目录 |
| 载体字 | v1.6.0 用日文字形拼汉字的旧方案，本工具**不使用** |
