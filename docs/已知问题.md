# 已知问题与历史结论

最后更新：2026-11-26

> 本文件只保留**仍然有效**的结论。已被推翻的判断直接删除，避免接手人照旧结论白折腾。

## 1. 登录页底部 4 行 / 深渊长文本：已解决，不是 locres 限制

症状：登录页底部 4 行、深渊 F_A（带破折号那段）、深渊外围层 `Reshanta_D` 一直显示英文/日文，怎么改译文都没反应。

根因：`source_hash` 必须等于 **`CRC32(官方源串的 UTF-32LE 字节)`**。旧代码把 UTF-8 字节逐字节扩展成 UTF-32LE 再算 CRC32，纯 ASCII 串结果相同，但含 `—`、`’`、`※` 等非 ASCII 字符的源串哈希全错，条目整体失效。

- 受影响：`en_src.json` 中 **477 条**含非 ASCII 的源串全部算错。
- 深渊 `Abyss_F_C` 是全 ASCII，一直正常，正好掩盖了问题。
- 修复：`zlib.crc32(s.encode('utf-32-le'))`。修复后 477 条全部命中，并已用游戏运行时内存里的英文原串交叉验证。
- 详见交接文档 §2.2.1。

> 旧文档"这 4 行 locres 覆盖不到、只能改 pak"的说法是**误判，已作废**。

## 2. 商城 / 套装名偶发显示原文

运行时拼接用的源串与 dat 原文可能不一致（例如多或少 ` (Bound)`）。需要按实际形态补多套哈希，脚本：`_内部工具\keyhunt\augment_hash_variants.py`。

## 3. 数量单位显示 K

程序固定先除以 1000 再拼单位字符串。改成「万」会让 744,175 显示成 `744.1万`（错十倍）。**决定：保留 K。**

## 4. 英文入口 / 日文入口都支持

- 英文入口：`source_hash` 用英文源串算；
- 日文入口：`source_hash` 用日文源串算。

旧文档"只支持英文入口"已作废——那次实测把英文哈希的 locres 放进了 `ja` 目录，当然不生效。

## 5. 条目数差异（153,238 / 153,210 / 153,029）

- 官方英文表（`map_en_clean.json`）：153,238 key → v0.0.2 英文入口载荷 AION2 命名空间 153,238 条；
- 官方日文表（`map_ja.json`）：153,210 key → 日文入口用「日文源表 + `oldja_hashes.json` 旧已验证哈希」拼满，最终同为 153,238 条；
- 历史语料 `plain_zh_v3.dat` / `plain_tw_v3.dat`：153,029 条；差额由 `tr_new_final_zh.json` 新增译文补齐。

日文源表比英文少、且部分源串在内存里被拼接/截断，所以日文入口**不能**只按新源表重算哈希，否则会丢老条目（见交接文档 §4.1 / §12 第 16 条）。

## 6. 日文入口的哈希来源

`oldja_hashes.json` 是从 v0.0.1 日文载荷里提取的 153,029 条已验证哈希，现已独立缓存，不再依赖 dist 里的旧版本包。重建时：有日文源串就用源串算，没有就沿用缓存，两者都没有的 key 不写。

## 7. Steam 校验完整性

校验只补官方 pak，**不会删**多出来的 locres。要彻底回到英文原版，用工具「一键还原」。

## 8. 游戏技改后部分技能仍显示英文（v0.0.3 已修）

11-26 更新改了 106 条已有 key 的原文（吟游星 37、元素师 15、战士 1、状态效果 3，其余为外观/道具/商店文本）。key 没变、原文变了 → 旧 `source_hash` 校验失败 → 回退英文。

- 修复方式：`_内部工具\keyhunt\patch_v0.0.3.json` 记录「key → 新英文原文 + 新简体译文」；`build_release.py` 统一应用，日文入口用同 key 的最新日文原文重算哈希。
- 校验：与 v0.0.2 载荷逐 key 比对，英文 106 条哈希全变、补丁外 0 变化；日文 64 条哈希变化、42 条日文原文未变。
- 内存抓取会混入噪声（别的 key 的片段、乱码），**只能人工确认后写补丁**，不能全量覆盖。详见交接文档 §4.8。
